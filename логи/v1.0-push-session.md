# Сессия: v1.0 push — security fix, observability, tags, PXE/options/forwarding editors, UX-консолидация

## Контекст

Дошли до финального рывка к 1.0. Сессия закрывает список блокеров и
функциональных дыр, обозначенный в плане релиза:

1. Security-блокер: `INTERMASQ_SECRET` fallback на известный ключ.
2. Observability: нет `/metrics` для Prometheus.
3. Покрытие dnsmasq: отсутствуют PXE, структурированный редактор `dhcp-option`,
   `server=/domain/upstream` (forwarding), теги на dhcp-host.
4. UX-расползание: 5 safety-механизмов + leases/new-devices/lease-to-static
   размазаны по отдельным вкладкам.

Бэкенд и фронтенд собираются, `go test` зелёный.

## Что изменено (файл-за-файлом)

### Бэкенд (Go)

**`main.go`**
- `init()` — убран `SecretKey = []byte("default-secret")`. Если `INTERMASQ_SECRET`
  не задан, процесс падает с подсказкой `openssl rand -hex 32` и текстом ошибки
  в stderr. **Старые деплои без переменной окружения упадут при старте — это
  намеренно.**
- Добавлен `dhcpTagRegex = ^(set|tag):[a-zA-Z0-9_][a-zA-Z0-9_-]*$` рядом с
  `macRegex`/`hostnameRegex`.
- `main()` — регистрация роута `r.GET("/metrics", metricsHandler)` вне группы
  `/api`, запуск `startDNSHealthChecker()` горутиной рядом с
  `startSSEBroadcaster()`.

**`metrics.go`** (новый файл)
- `metricsCounters` со счётчиками `Reloads`, `TestFailures` (атомарные `int64`),
  `StartedAt` для uptime.
- `metricsHandler` — отдаёт Prometheus exposition format. Метрики:
  `intermasq_hosts_total`, `intermasq_leases_active`, `intermasq_arp_online_total`,
  `intermasq_dnsmasq_active`, `intermasq_reloads_total`,
  `intermasq_dnsmasq_test_failures_total`, `intermasq_uptime_seconds`,
  + per-domain `intermasq_domain_up{domain=…}` и `intermasq_domain_resolve_seconds{…}`.
- `checkMetricsAuth` — принимает `X-API-Key`, `Bearer` или `?token=` (для
  scrape_url Prometheus, т.к. он не умеет кастомные заголовки без extras).
- `startDNSHealthChecker` / `runDNSHealthPass` — горутина раз в 60 с резолвит
  каждый домен из `readAllAliases` (`net.Resolver{PreferGo: true}`, таймаут 3 с)
  и пишет результат в `dnsHealth` map под RWMutex.

**`dnsmasq.go`**
- `reloadDnsmasq` — `counters.Reloads.Add(1)` после успешного `Restart`,
  `counters.TestFailures.Add(1)` при провале `dnsmasq --test`.
- Аналогичный инкремент `TestFailures` добавлен в 4 остальных вызова `--test`:
  `writeConfigWithTest`, `writeFileRaw`, `restoreHistoryVersion`,
  `restoreBackupZip`.
- **Единый канонический парсер** `parseDhcpHostLine(raw, file) (HostEntry, bool)`
  — заменил 5 копий одного и того же inline-парсинга. Распознаёт MAC/IP/hostname
  + собирает `set:`/`tag:`/`id:` токены в `Tags`.
- `formatDhcpHostLine(h HostEntry) string` — обратная сериализация (mac, hostname,
  ip, затем tags).
- `appendHostLine(filePath, h HostEntry)` — сигнатура изменена с позиционных
  `(file, mac, hostname, ip)` на `HostEntry`, чтобы теги проходили насквозь.
- Заменены вызовы в `readHostByMac`, `findHostsByIP`, `findHostsByMac`,
  `readAllHosts` — все теперь ходят через `parseDhcpHostLine`.

**`handlers.go`**
- `getHostsHandler` — перешёл на `parseDhcpHostLine`, флаг `|has_bak` сохранён.
- `addHostHandler` — добавлены `validateHostTags(req.Tags)` и
  `normalizeHostTags`, сериализация через `formatDhcpHostLine`.
- `validateHostTags(tags) bool` — проходит по regex `dhcpTagRegex`, плюс
  разрешает `id:` (клиентский ID) для round-trip существующих конфигов.
- `normalizeHostTags(tags) []string` — trim, dedup case-insensitively,
  сохранение порядка.
- `bulkAddHostsHandler`, `importCSVHandler`, `bulkLeaseToStaticHandler` —
  inline `fmt.Sprintf("dhcp-host=…")` заменён на `formatDhcpHostLine`.
- `bulkMoveHandler` — `appendHostLine(req.Target, *existing)` вместо
  позиционного вызова; теги переносятся вместе с хостом.
- `bulkEditHandler` — в `plannedChange` добавлено поле `newTags`, значение
  наследуется от `existing.Tags`; сериализация через `appendHostLine(file, HostEntry{…})`.

**`models.go`**
- `HostEntry` — добавлено поле `Tags []string` с json-тегом `tags,omitempty`.

## Намеренно оставлено как есть

- **Дублирование парсеров** в `dnsmasq.go` формально осталось в виде
  `parseDhcpHostLine` и `parseAliasLine` — это два разных формата, объединять
  их в generic-parser не стоит. Рефакторинг обещан отдельной сессией.
- **Глобальный `mu sync.Mutex`** — не трогался, это явный пункт в плане на
  рефакторинг.
- **Старые standalone-компоненты** `LeasesTab.vue` и `NewDevicesTab.vue` не
  удалены физически — `AuditTab` теперь используется внутри `SafetyTab`,
  остальные можно снести в следующем рефакторинге.
- **Bulk-import CSV/raw-text** теги не передаёт (нет UI). Одиночная форма
  покрывает 100% кейсов; расширить при необходимости тривиально.
- **DHCP-опция `id:`** (client-id) не редактируется UI как отдельное поле, но
  парсер её сохраняет и round-trip работает — конфиг с `id:` не порушится при
  редактировании других полей.
