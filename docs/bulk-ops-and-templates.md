# Bulk-операции и шаблоны конфигураций

Начиная с v3.0 в Intermasq добавлены групповые операции на хостах и шаблоны
для автоматизации добавления новых устройств.

---

## Auto next-IP

Автоматический подбор свободного IP-адреса в заданном диапазоне.

### Использование

В форме добавления хоста (single-режим) рядом с полем IP есть кнопка `🎲`:

1. Если выбран шаблон с заполненным `IP Range` — диапазон берётся из него.
2. Иначе появляется инпут для ввода CIDR (например `10.0.0.0/24`).
3. После нажатия `🎲` бэкенд ищет первый свободный IP в диапазоне
   (начиная с `network+1`, заканчивая `broadcast-1`), не занятый ни в одном
   `.conf` файле, и подставляет его в форму.

### Ограничения

- Только IPv4. IPv6-диапазоны вернут `ipv6_not_supported`.
- Маска `/31` и короче — `range_too_small`.
- Сканируется максимум 256 адресов от начала диапазона (защита от `/16`).
  Если за 256 итераций свободный IP не найден — `range_exhausted`.
- Свободность проверяется по статическим записям во всех `.conf` файлах
  в `-conf-dir`. Динамические аренды (leases) **не учитываются**.

### API

```
GET /api/hosts/next-ip?range=10.0.0.0/24
Authorization: Bearer <token>

→ 200 {"ip":"10.0.0.12"}
→ 400 {"error":"range_exhausted"}
```

## Шаблоны конфигураций

Предустановленные профили для быстрого добавления однотипных устройств.

### Создание шаблона

В форме добавления хоста нажмите `⚙️` — откроется модальное окно управления
шаблонами. Укажите:

| Поле | Описание | Пример |
|---|---|---|
| Name | Название шаблона | `IoT devices` |
| IP Range | Диапазон в формате CIDR | `10.0.5.0/24` |
| Hostname Pattern | Шаблон имени устройства | `iot-{NNN}` |
| Target File | Путь к `.conf` файлу | `/etc/dnsmasq.d/iot.conf` |

`{NNN}` в шаблоне имени заменяется на порядковый номер, дополненный нулями
до 3 знаков (`001`, `002`, ...). Номер = число существующих `dhcp-host=`
записей в целевом файле + 1.

### Применение шаблона

1. В форме добавления хоста выберите шаблон в dropdown над полями.
2. Введите MAC-адрес устройства.
3. Поля `IP`, `Hostname`, `File` заполнятся автоматически:
   - IP — следующий свободный в диапазоне шаблона,
   - Hostname — по паттерну с текущим индексом,
   - File — целевой файл шаблона (заблокирован от правок).
4. Перед сохранением поля можно скорректировать вручную.

### Хранение

Шаблоны хранятся в `/etc/intermasq/templates.json` (настраивается флагом
`-templates`). Файл создаётся автоматически при первом добавлении шаблона.
Формат — JSON, права `0600`.

### API

```
GET /api/templates
POST /api/templates         {"name":"...","ip_range":"...","hostname_pattern":"...","target_file":"..."}
DELETE /api/templates/:id
POST /api/hosts/apply-template   {"mac":"...","template_id":"..."}
```

`apply-template` **не пишет** в `.conf` файл — только возвращает предзаполненные
поля. Сохранение происходит через обычный `POST /api/hosts`.

## Bulk-move (перенос между файлами)

Перемещение выделенных хостов в другой `.conf` файл.

### Использование

1. В таблице хостов выделите нужные строки чекбоксами.
2. В появившейся панели нажмите `📦 Переместить`.
3. В модальном окне выберите целевой файл из списка существующих
   или введите свой путь.
4. Подтвердите — хосты будут удалены из исходного файла и дописаны
   в целевой.

### Поведение

- Хосты, уже находящиеся в целевом файле, переносятся в `skipped`
  (операция для них пропускается).
- Если IP или MAC хоста конфликтует с записью в целевом файле —
  хост попадает в `skipped`.
- Source = Target → `400 same_file`, операция отменяется целиком.
- Для каждого затронутого файла создаётся `.bak` перед изменением.
- Audit: запись с `action: "bulk_move"`, mac = `N moved, M skipped`.

### API

```
POST /api/hosts/bulk-move
{
  "hosts": [{"mac":"aa:bb:...","file":"/etc/dnsmasq.d/a.conf"}, ...],
  "target": "/etc/dnsmasq.d/b.conf"
}

→ 200 {"status":"ok","moved":2,"skipped":[]}
```

## Bulk-edit (массовая смена IP и hostname)

Изменение IP-префикса и/или hostname-суффикса у выделенных хостов.

### Использование

1. Выделите хосты в таблице.
2. Нажмите `✏️ Изменить` в панели выделения.
3. Заполните поля трансформации (оба блока опциональны):
   - **IP transform**: старый и новый префикс.
   - **Hostname transform**: суффикс для добавления и/или удаления.
4. В превью увидите первые 5 хостов с переходом `было → стало`.
5. Подтвердите — изменения применятся для всех выделенных хостов.

### Форматы IP-префикса

Поддерживаются два формата, определяются автоматически:

**3-октетная строка:**
- Старый: `10.0.0`, Новый: `10.0.1`
- `10.0.0.10` → `10.0.1.10`

**CIDR с маской:**
- Старый: `10.0.0.0/24`, Новый: `10.0.1.0/24`
- `10.0.0.10` → `10.0.1.10` (хост-часть переносится битово)

Требования:
- Форматы старого и нового должны совпадать (оба с `/` или оба без).
- В CIDR-режиме маски должны быть одинаковыми.
- Число октетов в строковом режиме должно совпадать.

### Транзакционность

**Всё или ничего.** Если хотя бы один хост из выделения вызывает конфликт
или ошибку валидации — вся операция отменяется, файлы не изменяются.

Проверки перед записью:
1. MAC и File каждого хоста валидны.
2. Хост существует в указанном файле (`readHostByMac`).
3. IP-префикс совпадает с текущим IP хоста.
4. Новый IP после трансформа валиден (`net.ParseIP`).
5. Hostname после трансформа соответствует `hostnameRegex`.
6. Нет внутренних дубликатов (два хоста → один новый IP).
7. Нет внешних дубликатов (новый IP не занят в других `.conf`).

### Hostname-трансформ

- `StripOld` — строка, которая убирается из конца hostname.
- `Suffix` — строка, которая дописывается в конец hostname.
- Порядок: сначала `StripOld`, потом `Suffix`.
- Оба поля опциональны — можно менять только IP или только hostname.

### API

```
POST /api/hosts/bulk-edit
{
  "hosts": [{"mac":"aa:bb:...","file":"/etc/dnsmasq.d/a.conf"}, ...],
  "ip_transform": {"old_prefix":"10.0.0","new_prefix":"10.0.1"},
  "hostname_transform": {"suffix":"-new","strip_old":"-old"}
}

→ 200 {"status":"ok","updated":3}
→ 409 {"error":"ip_duplicate","conflicts":[...]}
→ 400 {"error":"prefix_not_matched","mac":"aa:bb:...","old_ip":"192.168.1.5"}
```

### Коды ошибок bulk-edit

| Код | Значение |
|---|---|
| `invalid_data` | Неверный MAC или путь файла |
| `no_hosts` | Пустой список хостов |
| `both_prefixes_required` | Указан только один префикс |
| `prefix_format_mismatch` | Старый и новый в разных форматах |
| `prefix_mismatch` | В CIDR-режиме маски не совпадают |
| `invalid_prefix_format` | Не CIDR и не 3-октетная строка |
| `invalid_cidr` | CIDR не парсится |
| `ipv6_not_supported` | IPv6-диапазон |
| `prefix_not_matched` | IP хоста не подпадает под старый префикс |
| `invalid_ip` | Новый IP после трансформа невалиден |
| `invalid_hostname` | Hostname после трансформа не соответствует regex |
| `ip_duplicate_bulk` | Внутренний конфликт — два хоста → один IP |
| `ip_duplicate` | Внешний конфликт — IP занят в другом файле |
| `host_not_found` | Хост не найден в указанном файле |
| `file_write_error` | Ошибка записи (после этого файлы откатываются `.bak`) |

## Audit

Все новые операции пишутся в аудит-лог (`/etc/intermasq/audit.log`):

| Action | Поле Mac | Поле Ip |
|---|---|---|
| `bulk_move` | `N moved, M skipped` | — |
| `bulk_edit` | `N hosts` | `old_prefix -> new_prefix` |

Записи видны во вкладке «История» в UI.

---

## Безопасность

- Все новые эндпоинты требуют `Authorization: Bearer <token>` (или `X-API-Key`).
- `isSafePath` проверяет, что все пути файлов остаются в пределах `-conf-dir`.
- `TargetFile` в шаблонах проходит `isSafePath` при создании.
- `.bak` файлы создаются перед каждой bulk-операцией для каждого
  затронутого `.conf` — можно откатить через кнопку `⏪ Откат` в UI.
- Auto-reload dnsmasq **не выполняется** после bulk-операций —
  пользователь применяет изменения вручную через кнопку «Применить»,
  как и раньше.
