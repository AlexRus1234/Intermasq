# DNS aliases (A / CNAME / PTR / TXT)

Начиная с v3.0 в Intermasq добавлена отдельная вкладка «DNS» для управления
локальными DNS-записями dnsmasq четырёх типов:

- **A**     — `address=/domain/IP`         (домен → IPv4-адрес)
- **CNAME** — `cname=alias,target`         (алиас → другой домен)
- **PTR**   — `ptr-record=name,target`     (reverse DNS: IP → домен)
- **TXT**   — `txt-record=name,value`      (произвольный текст: SPF/DKIM/метки)

Это типичный HomeLab-кейс: вместо того чтобы держать в голове IP-адрес
сервера, вы задаёте ему имя `nas.lan` и обращаетесь по нему из браузера,
`dig`, мессенджеров и т.д. PTR и TXT закрывают оставшиеся сценарии —
reverse DNS для почтовых релеев и TXT-значения для SPF/DKIM/ACME.

---

## Что было раньше

Раньше Intermasq работал только с `dhcp-host=` (вкладка «Статика») и с
общими директивами dnsmasq через вкладку «Настройки dnsmasq».
`address=`/`cname=` попадали в общую кучу директив и не имели
специализированного UI: их нельзя было добавить в один клик, не было
проверки дублей по домену, не было bulk-импорта.

## Что появилось

- **Вкладка «DNS»** в шапке (между «Статика» и «Аренды»).
- CRUD для четырёх типов записей (A / CNAME / PTR / TXT) с валидацией и
  проверкой дублей.
- **Bulk-импорт** сырым текстом и CSV.
- **CSV-экспорт** (кнопка `📥 CSV` на вкладке DNS).
- **Файл по умолчанию** `10-dns-aliases.conf` — создаётся автоматически
  при первом добавлении без явного выбора файла.
- **Кнопка «Откат»** на каждый файл (как в «Статике»).
- Записи **исключены** из вкладки «Настройки dnsmasq», но **сохраняются**
  при пересохранении файла через неё.

## Форматы записей

### A-запись (`address=/domain/IP`)

| Поле dnsmasq | Пример            |
|--------------|-------------------|
| `address=`   | `address=/nas.lan/192.168.1.10` |

В UI:
- **Domain** — `nas.lan` (домен без слэшей).
- **Target** — `192.168.1.10` (IPv4-адрес).

> Wildcard-формы `address=/#/IP` (перехват всех запросов) и
> `address=/*.domain/IP` (wildcard поддоменов) **не поддерживаются** в
> UI — парсер их отклоняет. Это сделано сознательно: такие записи нужны
> для captive portal и выходят за пределы HomeLab-кейса. При
> необходимости их можно добавить вручную в `.conf`-файл — Intermasq их
> не тронет, но и не покажет в таблице.

### CNAME-запись (`cname=alias,target`)

| Поле dnsmasq | Пример                |
|--------------|-----------------------|
| `cname=`     | `cname=wiki,nas.lan`  |

В UI:
- **Domain** — `wiki` (алиас, который будет резолвиться).
- **Target** — `nas.lan` (целевой домен, на который указывает алиас).

> Tagged-форма `cname=alias,target,tag:lan` парсится корректно (тег
> игнорируется, alias/target попадают в таблицу). При редактировании
> через UI тег будет потерян — при необходимости используйте вкладку
> «Настройки dnsmasq» (там `cname=` как директива) или редактируйте файл
> вручную.

### PTR-запись (`ptr-record=name,target`)

| Поле dnsmasq | Пример                                |
|--------------|---------------------------------------|
| `ptr-record=` | `ptr-record=10.1.168.192.in-addr.arpa,nas.lan` |

В UI:
- **Domain** — `10.1.168.192.in-addr.arpa` (имя reverse-зоны для IP).
- **Target** — `nas.lan` (FQDN, на который указывает PTR).

Это позволяет `dig -x 192.168.1.10` возвращать `nas.lan` вместо
`10.1.168.192.in-addr.arpa`. Требуется для:
- Postfix / sendmail с GSSAPI-аутентификацией.
- Kerberos realm discovery.
- Любых self-hosted приложений, проверяющих соответствие прямого и
  обратного резолва (FcrDNS).

> Формула имени reverse-зоны: перевернуть октеты IP и добавить
> `.in-addr.arpa`. Для `192.168.1.10` → `10.1.168.192.in-addr.arpa`.

> dnsmasq допускает несколько имён reverse-зоны в одной директиве
> (`ptr-record=name1,name2,target`). UI работает с одним именем —
> парсер берёт первый и последний токены. Если нужно несколько,
> редактируйте файл вручную.

### TXT-запись (`txt-record=name,value`)

| Поле dnsmasq | Пример                            |
|--------------|-----------------------------------|
| `txt-record=` | `txt-record=nas.lan,v=spf1 -all` |

В UI:
- **Domain** — `nas.lan` (домен, к которому привязывается запись).
- **Target** — `v=spf1 -all` (произвольный текст).

Сценарии:
- **SPF**: `txt-record=example.lan,v=spf1 mx -all`
- **DKIM**: `txt-record=dkim._domainkey,k=rsa; p=MIGfMA0GCSqGSIb3...`
- **ACME DNS-01**: `txt-record=_acme-challenge.nas.lan,<token>`
- **mDNS-SD / Service Discovery** метаданные.

> TXT-значение может содержать запятые (например, DKIM с `k=rsa; p=…`).
> Парсер сплитит только по первой запятой, остаток — значение целиком.

> dnsmasq допускает значения с пробелами только в кавычках
> (`txt-record=name,"multi word"`). UI принимает произвольный текст
> без новой строки — если нужно работать с multi-line значениями,
> редактируйте файл вручную.

## Добавление записей

### Одиночное добавление

1. Перейдите на вкладку «DNS».
2. В форме сверху выберите тип (**A** / **CNAME** / **PTR** / **TXT**).
3. Заполните **Domain** и **Target**. Placeholder подскажет формат:
   - A → IP-адрес (`192.168.1.10`)
   - CNAME / PTR → целевой домен (`nas.lan`)
   - TXT → текстовое значение (`v=spf1 -all`)
4. Под формой отображается live-превью итоговой строки:
   - `address=/nas.lan/192.168.1.10`
   - `cname=wiki,nas.lan`
   - `ptr-record=10.1.168.192.in-addr.arpa,nas.lan`
   - `txt-record=nas.lan,v=spf1 -all`
5. Поле **File** можно оставить пустым — будет создан
   `10-dns-aliases.conf`. Либо выберите существующий файл через
   nav-tabs под формой.
6. Нажмите «Добавить».

### Редактирование

1. Нажмите ✏️ напротив записи в таблице.
2. Форма сверху перейдёт в жёлтый режим «Редактирование».
3. Измените поля и нажмите «Сохранить».
4. Старая запись будет удалена, новая добавлена (даже если она переносится
   в другой файл).

### Удаление

- Одиночное — кнопка ✕ в строке + confirm.
- **Bulk-delete чекбоксами не реализован** (только bulk import).

## Импорт

### Raw-текст

1. В форме выберите режим «Импорт списком».
2. Вставьте текст в textarea. Поддерживается 8 форматов на строку:

```
A nas.lan 192.168.1.10
CNAME wiki nas.lan
PTR 10.1.168.192.in-addr.arpa nas.lan
TXT nas.lan v=spf1 -all
address=/nas.lan/192.168.1.10
cname=wiki,nas.lan
ptr-record=10.1.168.192.in-addr.arpa,nas.lan
txt-record=nas.lan,v=spf1 -all
```

3. Счётчик «Распознано: N записей» обновляется live.
4. Укажите файл назначения (или оставьте дефолтный).
5. Нажмите «Импортировать».

### CSV

1. В форме выберите режим «CSV файл».
2. Выберите `.csv`-файл. Формат — 3 колонки: `type,domain,target`:

```csv
type,domain,target
A,nas.lan,192.168.1.10
A,printer.lan,192.168.1.20
CNAME,wiki,nas.lan
PTR,10.1.168.192.in-addr.arpa,nas.lan
TXT,nas.lan,v=spf1 -all
```

3. Укажите файл назначения.
4. Нажмите «Импортировать».

Header-строка (`type,domain,target`) пропускается автоматически.

### Экспорт CSV

Кнопка `📥 CSV` в шапке на вкладке DNS скачивает `intermasq_aliases.csv`
со всеми записями. (На других вкладках эта кнопка экспортирует хосты —
поведение контекстно-зависимое.)

## Валидация и защита

- **Дубли по домену:** при добавлении проверяются все `.conf`-файлы. Если
  домен уже существует в другой записи — операция блокируется с 409 и
  указанием конфликтующей записи.
- **Регулярные выражения:**
  - Domain: `^[a-zA-Z0-9]([a-zA-Z0-9-.]*[a-zA-Z0-9])?$` (принимает
    `nas`, `nas.lan`, `a-b.c.d`; отвергает `.nas`, `nas.`, `..`).
  - Target для A: валидный IPv4 (через `net.ParseIP`).
  - Target для CNAME / PTR: тот же regex, что и для domain.
  - Target для TXT: любой непустой текст без символа новой строки
    (принимает `v=spf1 -all`, `k=rsa; p=…`, URI, произвольные значения).
- **`createLocalBackup`** перед каждым изменением → `.bak`-копия файла.
- **Кнопка «Откат»** восстанавливает файл из `.bak` (одна операция).
- **Audit-лог:** действия `alias_add`, `alias_delete`, `alias_bulk_add`
  записываются в `/etc/intermasq/audit.log` и видны во вкладке «История».
- **Path Traversal:** все пути проверяются через `isSafePath` (запись
  только внутри `-conf-dir`).
- **Pre-flight `dnsmasq --test`** **не вызывается** на каждое
  добавление/удаление alias (как и для `dhcp-host`). Синтаксис
  `address=`/`cname=`/`ptr-record=`/`txt-record=` прост и валидируется
  regex'ом. Проверка происходит при нажатии кнопки «Применить» в шапке —
  она запускает `dnsmasq --test` и перезапускает демон только при успехе.

## Файл по умолчанию

При первом добавлении записи без явного выбора файла создаётся:

```
/etc/dnsmasq.d/10-dns-aliases.conf
```

С содержимым:

```
# DNS aliases managed by Intermasq
# Format: address=/domain/IP  or  cname=alias,target
```

Последующие добавления без выбора файла дописываются в этот же файл.
Если вы хотите разнести записи по нескольким файлам (например,
`iot-dns.conf` для умного дома) — создайте файл через nav-tab «Все
файлы» → выберите его → добавляйте записи.

## Сосуществование с другими вкладками

### Вкладка «Статика» (`dhcp-host=`)

`dhcp-host=` и `address=`/`cname=` — независимые директивы dnsmasq.
Запись `dhcp-host=aa:bb:cc:dd:ee:ff,nas,192.168.1.10` резолвит `nas` в
`192.168.1.10` **только если** `expand-hosts` включён и есть `domain=`.
A-запись `address=/nas.lan/192.168.1.10` работает всегда, без
зависимости от опций dnsmasq. Рекомендуется использовать **либо** одно,
**либо** другое для одного имени, чтобы избежать конфликтов.

### Вкладка «Настройки dnsmasq»

`address=` и `cname=` **исключены** из Config-вкладки (как и
`dhcp-host=`) — ими управляет только вкладка «DNS». Но при пересохранении
файла через Config-вкладку alias-строки **сохраняются** в исходном виде
(не затираются). Порядок в файле:

1. Header-комментарии (`# ...`)
2. `dhcp-host=` строки
3. `address=` / `cname=` строки
4. Управляемые директивы (сортировка по группам: DNS < DHCP < Log < Other)

## API

### `GET /api/aliases`

**Ответ:** массив `DnsAliasEntry`

```json
[
  {"type": "A",     "domain": "nas.lan", "target": "192.168.1.10", "file": "/etc/dnsmasq.d/10-dns-aliases.conf"},
  {"type": "CNAME", "domain": "wiki",    "target": "nas.lan",      "file": "/etc/dnsmasq.d/10-dns-aliases.conf|has_bak"}
]
```

> Поле `file` может содержать суффикс `|has_bak`, если рядом с файлом
> есть `.bak`-копия. Фронтенд использует это для отображения кнопки
> «Откат».

### `POST /api/aliases`

**Тело:** `DnsAliasEntry`

```json
{"type": "A", "domain": "nas.lan", "target": "192.168.1.10", "file": ""}
```

- `file` пустой → создаётся `10-dns-aliases.conf`.
- При дублировании домена → `409 {"error":"alias_duplicate","conflicts":[...]}`.

**Ответ 200:** `{"status": "ok"}`

### `POST /api/aliases/bulk`

**Тело:** `BulkAliasReq`

```json
{
  "file": "",
  "aliases": [
    {"type": "A",     "domain": "nas.lan",     "target": "192.168.1.10"},
    {"type": "CNAME", "domain": "wiki",        "target": "nas.lan"},
    {"type": "CNAME", "domain": "cloud",       "target": "nas.lan"}
  ]
}
```

Проверяет intra-batch дубли (два одинаковых домена в массиве) и
cross-config дубли (домен уже есть в `.conf`). Существующие в файле
записи с тем же доменом **перезаписываются** (старая удаляется, новая
добавляется).

**Ответ 200:** `{"status": "ok", "count": 3}`

### `POST /api/aliases/delete`

> Удаление реализовано через `POST` (а не `DELETE`), т.к. gin плохо
> переваривает точки в path-параметрах (`DELETE /api/aliases/nas.lan`).

**Тело:** `DeleteAliasReq`

```json
{"type": "A", "domain": "nas.lan", "file": "/etc/dnsmasq.d/10-dns-aliases.conf"}
```

**Ответ 200:** `{"status": "deleted"}`
**404:** `{"error": "alias_not_found"}`

### `GET /api/aliases/csv`

Скачивает `intermasq_aliases.csv`. Формат:

```csv
type,domain,target
A,nas.lan,192.168.1.10
CNAME,wiki,nas.lan
```

### `POST /api/aliases/csv`

**FormData:**
- `file` — CSV-файл.
- `target_file` (опционально) — путь к файлу назначения. Если пустой —
  используется `10-dns-aliases.conf`.

**Ответ 200:** `{"status": "ok", "count": N}`

## Пример сценария: named-хосты для HomeLab

1. **Открыть вкладку «DNS».**
2. **Добавить A-запись для NAS:**
   - Type: `A`
   - Domain: `nas.lan`
   - Target: `192.168.1.10`
   - File: (пусто → создастся `10-dns-aliases.conf`)
3. **Добавить CNAME-алиасы:**
   - Type: `CNAME`, Domain: `wiki`,    Target: `nas.lan`
   - Type: `CNAME`, Domain: `cloud`,   Target: `nas.lan`
   - Type: `CNAME`, Domain: `printer`, Target: `192.168.1.20` ← **ошибка!**
     CNAME не может указывать на IP. Используйте A-запись.
4. **Нажать «Применить»** в шапке → `dnsmasq --test` + restart.
5. **Проверить:**
   ```bash
   dig @192.168.1.1 nas.lan    # → A 192.168.1.10
   dig @192.168.1.1 wiki       # → CNAME nas.lan → A 192.168.1.10
   dig @192.168.1.1 cloud      # → CNAME nas.lan → A 192.168.1.10
   ```
6. **Открыть `http://nas.lan`** в браузере.

## Частые вопросы

**Q: Почему `dig` показывает только A, без CNAME?**
A: Проверьте, что вы добавили запись через «Применить» (не просто
«Добавить»). `dig @<ip_сервера> <домен>` явно обращается к dnsmasq; если
используете системный resolver — убедитесь, что `/etc/resolv.conf`
указывает на dnsmasq.

**Q: Можно ли иметь A и CNAME с одинаковым доменом?**
A: Нет — это конфликт в dnsmasq. При попытке добавить CNAME `wiki` если
уже есть A `wiki` — вернётся 409 `alias_duplicate`. Сначала удалите
старую запись.

**Q: Как перенести записи из старого конфига?**
A: Скопируйте строки `address=/...` и `cname=...` в textarea bulk-импорта
(режим «Импорт списком»). Парсер распознает их автоматически.

**Q: Где хранятся записи?**
A: В любом `.conf`-файле в `-conf-dir` (по умолчанию `/etc/dnsmasq.d/`).
По умолчанию Intermasq создаёт `10-dns-aliases.conf`, но можно выбрать
любой существующий файл через nav-tabs.
