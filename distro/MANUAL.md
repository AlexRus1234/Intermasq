# Intermasq Lab: ручной walkthrough

Лаборатория предназначена для быстрого прохода по GUI. Все три панели
независимы, но используют один и тот же набор демонстрационных сценариев.

## Доступ

| Профиль | Панель | Сеть | Назначение |
|---|---:|---|---|
| office | `8082` | `10.10.1.0/24` | DHCP, статика и DNS |
| lab | `8083` | `10.10.2.0/24` | редактор конфигурации и восстановление |
| demo | `8084` | `10.10.3.0/24` | discovery, SSE, plugin и metrics |

Общая тестовая учётная запись:

```text
admin / intermasq-lab
```

При первом запуске также создаётся пользователь для RBAC:

```text
operator / operator-lab
```

## 1. Общая оболочка

На каждой панели проверить:

1. Войти под `admin`.
2. Убедиться, что статус `dnsmasq` зелёный.
3. Переключить русский/английский язык.
4. Переключить светлую/тёмную тему.
5. Открыть Swagger через меню.
6. Открыть `/metrics` в новой вкладке.
7. Выйти и войти снова.

На `demo` оставить панель открытой для проверки SSE в следующих шагах.

## 2. Статика: профиль office

Вкладка «Статика» должна содержать несколько хостов с MAC, IP, hostname,
tags и lease-time. У `office-laptop` должна гореть зелёная online-лампочка,
а `office-printer` должен оставаться offline.

Проверить:

1. Поиск по MAC, IP и hostname.
2. Сортировку по каждому столбцу.
3. Редактирование существующего хоста.
4. Добавление нового хоста с `set:iot` и `lease-time=12h`.
5. Подсказку следующего свободного IP.
6. Экспорт CSV.
7. Импорт CSV в отдельный конфигурационный файл.
8. Bulk-edit префикса IP и суффикса hostname.
9. Bulk-move в другой `.conf`.
10. Массовое удаление одного тестового хоста.
11. Открытие истории изменённого файла.
12. Просмотр diff и восстановление версии.
13. Одношаговый rollback по `.bak`.

В модальном окне шаблонов проверить `office-laptop` и `office-iot`, затем
применить один шаблон к тестовому MAC.

## 3. DNS: профили office и demo

Вкладка «DNS» содержит все четыре типа:

- `A`: `laptop.office.test`, `printer.office.test`;
- `CNAME`: `printer-alias.office.test`;
- `PTR`: обратная запись для `10.10.1.10`;
- `TXT`: `lab-info.office.test`.

Проверить:

1. Фильтрацию и сортировку.
2. Preview директивы в форме.
3. Добавление и удаление тестовой записи.
4. Bulk import нескольких DNS-записей.
5. CSV export/import.
6. Историю и diff файла DNS.

## 4. Обнаружение: профиль demo

Вкладка «Обнаружение» содержит две независимые группы:

1. Unknown ARP devices: heartbeat-устройство должно быть в статике и не
   отображаться как unknown.
2. New DHCP leases: lease от устройства, отсутствующего в `dhcp-host`, должен
   отображаться в нижней таблице.

Проверить:

1. ARP-лампочки online/offline.
2. OUI/vendor lookup.
3. Переход неизвестного ARP-устройства в форму статики.
4. Выбор одного lease и перенос в статику.
5. Выбор нескольких leases и bulk-перенос.
6. Жёлтое предупреждение о необходимости отдельного Apply.
7. Нажатие Apply после bulk lease-to-static.

Для SSE оставить вкладку открытой и перезапустить heartbeat или `dnsmasq`:
изменение ARP/status должно прийти без ручного обновления страницы.

## 5. Конфигурация: профиль lab

Вкладка «Настройки dnsmasq» должна показывать несколько файлов:

- `lab-main.conf` — DHCP range, domain и базовые директивы;
- `lab-devices.conf` — хосты и DNS-записи;
- `lab-options.conf` — RFC 2132 DHCP options;
- `lab-pxe.conf` — TFTP/PXE;
- `lab-forwarder.conf` — `server=` и domain forwarding.

Проверить:

1. Переключение файлов табами.
2. Визуальное редактирование `dhcp-range`.
3. RFC 2132 presets для DHCP options.
4. Добавление `server=/domain/upstream`.
5. PXE/network boot директивы.
6. Создание нового файла через каждый preset:
   `empty`, `basic-dhcp`, `forwarder`, `pxe`, `aliases`.
7. Удаление отдельного тестового файла.
8. Raw-чтение файла.
9. Raw-запись валидной директивы.
10. Raw-запись ошибочной директивы и автоматический rollback.
11. Историю, diff, restore и `.bak` rollback.

## 6. Backup, audit и templates

Во вкладке «Безопасность»:

1. Открыть список host templates.
2. Создать и удалить тестовый template.
3. Скачать ZIP backup.
4. Изменить тестовый `.conf`.
5. Восстановить ZIP.
6. Убедиться, что перед restore создан `.restore.bak`.
7. Открыть audit log.

Audit должен содержать действия с host, DNS, template, history, backup и
restore.

## 7. RBAC: любой профиль

1. Войти под `operator / operator-lab`.
2. Убедиться, что вкладка Users отсутствует.
3. Убедиться, что скрыты Apply, Restore, Raw write и restart.
4. Открыть доступные read/add операции.
5. Попробовать вызвать admin endpoint через Swagger: должен быть отказ.
6. Войти под `admin`.
7. Создать временного пользователя.
8. Удалить временного пользователя.
9. Сменить пароль admin и проверить отзыв старого JWT.

## 8. Plugin и эксплуатация: профиль demo

В меню должен появиться `Intermasq Lab Plugin`.

1. Открыть plugin в полноэкранном overlay.
2. Убедиться, что он отвечает через Unix-сокет.
3. Перезапустить Intermasq через меню.
4. Повторно открыть plugin и убедиться, что sidecar не продублировался.
5. Проверить `/metrics` до и после изменения lease/ARP.
6. Проверить `/swagger/index.html`.

## 9. Негативные проверки

В профиле `lab` безопасно выполнить на временных файлах:

1. Неправильный MAC.
2. Неправильный IP.
3. Дублирующий MAC.
4. Имя файла без `.conf`.
5. Имя файла с `/` или `\\`.
6. Путь за пределами `conf-dir`.
7. Некорректный raw dnsmasq syntax.
8. Повреждённый ZIP.
9. Пустой bulk import.
10. Более 10 неудачных login с одного IP.

## 10. Сброс лаборатории

Обычный restart сохраняет данные:

```sh
rc-service intermasq-lab restart
```

Для полного возврата demo-состояния остановить сервис, удалить только
`/var/lib/intermasq-lab`, затем запустить его снова. Это удаляет users, audit,
history, templates и изменения конфигурации, но не трогает сам образ.
