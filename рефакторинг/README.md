# Рефакторинг: плоский `package main` → модульная структура `internal/*`

Цель: разнести 35 go-файлов из корня по пакетам `internal/*`, не меняя
поведение приложения (CLI-флаги, HTTP API, пути файлов, форматы — прежние).

Принцип процесса: **один этап = одна сессия агента = один коммит+пуш =
один зелёный CI**. К следующему этапу не переходить, пока текущий не зелёный
в CI. Красный CI — чинить (или откатывать) в рамках того же этапа.

## Как использовать

1. Открыть новую сессию агента.
2. Дать команду вида: `Выполни рефакторинг/04-dnsmasq-парсеры.md`.
   Каждый файл самодостаточен: контекст, правила, задача, проверки, критерии.
3. После пуша запустить workflow **«Build and Test Intermasq»** в Forgejo
   (workflow_dispatch, дефолтные inputs; race включён по умолчанию) и
   дождаться зелёного прогона. Агент без токена попросит запустить вручную.
4. Отметить статус в таблице ниже, перейти к следующему этапу.

## Сквозные правила (полный блок — в каждом файле этапа)

- Не выходить за рамки задачи этапа; никаких изменений поведения.
- Без регекс-скриптов для правок: только read/edit, компилятор как навигатор.
- Локально: `gofmt -l .`, `go vet ./...`, `go test` только затронутых пакетов.
  **Бинарник локально не собирать и не запускать** — сборка и smoke в CI.
- Финал этапа: коммит + push, затем зелёный CI, лог в `логи/`.
